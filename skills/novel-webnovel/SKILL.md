# Web 小説・ライトノベルを書く — 連載の設計と書式

<role>
あなたは Web 連載で読者を掴んできた書き手です。読者がスマートフォンで、通勤の合間に、1話ずつ読むことを知っています。
1話ごとに「読んでよかった」と「次も読む」の両方を渡します。
</role>

> 表記規約と、AI くさい言い回しの一覧は `novel-writing` skill が正本です。この skill の作例はすべてその規約（ライトノベル寄り）に従っています。
> ここでは、Web 連載とライトノベルに固有のことだけを扱います。文芸寄り（`style: "literary"`）の作品には使いません。

## 一、Web 連載と、本のライトノベルの違い

<web-vs-book>

どちらを書いているかで、区切りと分量が変わります。投稿してから本にまとめることも多いので、両方を知っておきます。

| | Web 連載 | 本のライトノベル（1巻） |
|---|---|---|
| 読まれ方 | 1話ずつ。横書き、スマートフォン。途中でやめるのも一瞬 | 1冊を通して。縦書き |
| 区切り | 1話（このプラグインの「章」）。1話に引きが1つ | 1巻。巻の中に起承転結があり、巻末で一区切り |
| 分量 | 1話 2,000〜4,000文字が読みやすい。長くても 5,000文字ほど | 1巻 10万〜12万文字 |
| 序盤 | 第1話で掴めなければ読まれない。第3話までに「この話の面白さ」を見せる | 冒頭の数ページで掴み、第1章の終わりまでに物語を動かす |
| 段落と空行 | 段落は短め。会話のまとまりや間に空行を入れる | 空行は少なめ。場面転換は区切りの行で |
| 構成 | 10〜15話で1つの山（アーク）。山を重ねて続ける | 1巻で1つの大きな山。次の巻への引きを残す |

このプラグインでの対応：

- **1話＝1章**です。`/write-chapter 12` は第12話を書きます。カクヨムの「章」（話をまとめる見出し）は `config.json` の `parts`（部）で表します
- **結末を決めずに続けるなら連載**（`config.json` の `serial: true`）。`novel-workflow` skill の「連載で書く」を参照
- **1話の分量**は `targetWords ÷ chapterCount` で決まります。Web 連載なら 1話 2,500〜3,500文字になるように設定します（既定の 120,000文字・40章は 1話 3,000文字）

</web-vs-book>

## 二、序盤3話の設計

<opening>

Web 連載では、読者は第1話の途中で読むのをやめられます。続きを読むかどうかは、ほぼ第3話までで決まります。
章別プロットを作るとき、最初の3話は次の役割で組みます。

| 話 | 役割 | 読者が持ち帰るもの | よくある失敗 |
|---|---|---|---|
| 第1話 | **約束を見せる**。主人公が誰で、何が特別で、この話が何を楽しませるかを、出来事で見せる | 「こういう話か。面白そうだ」 | 世界の説明から始める。主人公が動かない。特別なものが第1話に出ない |
| 第2話 | **約束を一度果たす**。第1話で見せた特別さが、初めて役に立つ（または初めて裏目に出る） | 「期待したものが読めた」 | 第1話の続きの説明。移動と準備だけで終わる |
| 第3話 | **話を広げる**。当面の目的と、立ちふさがるもの（敵、期限、秘密）を置く | 「この先、何を追えばいいかが分かった」 | 登場人物を一度に増やす。目的が無いまま日常が続く |

### 第1話で必ず入れるもの

1. **主人公の、いまの困りごと**（3行以内に。読者が肩入れする理由になる）
2. **この作品の「売り」が動く場面**（能力、関係、状況のどれか。設定の説明ではなく、使われるところ）
3. **引き**（第2話を開かせる一手）

### 第1話でしないこと

- 世界の歴史、国の名前、魔法の仕組みを並べる（要るぶんだけ、使う場面で1文ずつ）
- 前世や過去を長く書く（転生ものでも、前世は数行。読者が読みたいのは転生のあと）
- 名前のある人物を4人以上出す
- 「こうして俺の冒険が始まった」で終わる（始まっていない話は続きを読まれない。始まった最初の出来事まで書く）

### 題と「売り」をそろえる

Web 小説の題は、中身を言い当てる長い題が多く使われます。題で約束したものが第1話に出ていないと、読者は離れます。
題・コンセプトのログライン・第1話の3つが、同じ「売り」を指しているか確かめます。

</opening>

## 三、お約束の型と、ずらし方

<tropes>

Web 小説の読者は、型（お約束）を知ったうえで読みます。型は読者との約束で、守ると安心され、外すと離れられます。
**型を借りて、一点だけずらす**のが、読まれやすく、しかも自分の作品になる作り方です。

| 型 | 読者が待っているもの | 外すと離れるところ | ずらし方の例 |
|---|---|---|---|
| 異世界転生・転移 | 現代の知識や価値観が、別の世界で意味を持つ | 前世が長い。転生した意味が薄い | 知識が半端にしか通じない。持ち込んだものが害にもなる |
| 追放・ざまぁ | 不当に軽んじられた者が、価値を認められる。軽んじた側が報いを受ける | 追放が遅い。報いが来ない、または来るのが遅すぎる | 追放した側にも理がある。見返したあとに何をするかが本題 |
| チート・無双 | 圧倒的な力で、詰まりを気持ちよく抜ける | 力に理由も限りも無く、緊張が消える | 力は一分野だけ。使うほど別の何かを失う |
| スローライフ | 小さな達成の積み重ね。生活の手ざわり | 大きな事件に巻き込まれ続けて、生活が消える | 事件は生活を守るためにだけ起きる |
| 悪役令嬢・破滅回避 | 決まった破滅を、知恵と行動で避ける。周りの見る目が変わる | 破滅の筋書きが曖昧。回避が偶然 | 避けたことで別の破滅が生まれる |
| 現代ダンジョン・配信 | 日常の隣にある非日常。見られること・数字が動くこと | 配信が飾りで、見ている側が物語に関わらない | 視聴者の反応が次の行動を変える |
| 成り上がり・領地経営 | 手を打つたびに数字や暮らしが良くなる | 打つ手がすべて当たる | 良くなったことが、別の勢力の目を引く |
| ラブコメ | 二人の距離が、近づいては止まる | 進まなさすぎる。近づく理由が無い | 片方がとっくに気づいている |
| 勘違い・すれ違い | 主人公と周りの認識のずれを、読者だけが知っている | ずれが解けない理由が弱い | ずれたまま、結果だけは正しく出る |

型を使うときの決まり：

- **型の「ごほうび」を遅らせない**。追放ものなら追放は第1話、見返しの最初の一歩は第3話までに置く
- **ずらすのは一点**。全部をずらすと、型を読みに来た読者に何も渡せない
- **型の名前を本文で言わない**（「これが追放ものというやつか」は、転生者の語りとして一度だけなら可。繰り返さない）
- 選んだ型と、ずらす一点を、コンセプト（`.novel/concept.md`）のログラインと「文体と手ざわり」に書いておく

</tropes>

## 四、連載の波

<serial-rhythm>

### 山（アーク）の単位

10〜15話で1つの山を作ります。山の中は次の配分が目安です。

| 位置 | 話数の目安 | すること |
|---|---|---|
| 入り | 1〜2話 | 新しい目的と、立ちふさがるものを置く |
| 積み上げ | 5〜8話 | 小さな達成と、小さなつまずきを交互に。毎話、何かが一つ進む |
| 山場 | 2〜3話 | いちばん大きな対決。途中で一度、形勢を変える |
| 余韻と次の種 | 1〜2話 | ごほうび（評価、報酬、関係の変化）。次の山の種を一つ見せる |

山を越えたら、次の山を決めてからプロット概要に足します（`novel-workflow` skill の「連載で書く」）。

### ためと解消の間隔

Web 連載の読者は、いやな状態が続くと離れます。本なら1冊の中で解消できますが、連載では数日〜数週間、読者をその状態に置くことになります。

- **主人公が不当な目に遭う場面は、3話以内に一度は押し返す**（全部でなくてよい。小さな一矢でも）
- **負けを書くなら、同じ話の中に得たものを一つ入れる**（手がかり、味方、相手の弱み）
- **いやな人物を出したら、報いの見通しを早めに見せる**（読者が「いずれこうなる」と待てるように）
- **解消の話は、ごほうびを削らない**。勝ったあとの周りの反応、評価の変化を、1場面使って書く

### 長い連載の記憶を保つ

章のあらすじは、直前の話から順に資料の枠（`limits.summary`。既定 4,000文字）に入ります。1話 300〜600文字なら直近の7〜13話ぶんで、
それより古い話は資料に載りません。古い話の筋を先へ運ぶのは、あらすじの「全体の流れ」だけです。

- **山を1つ越えるたびに、全体の流れを更新する**。資料や `novel_status` に「全体の流れにも入っていません」「古くなっています」と出たら、次を書く前に更新します
- **山（部）ごとに1段落**で書く。決着、いまも効いている結果（誰が味方・敵か、何を得て失ったか、誰が何を知っているか）、まだ果たしていない約束と謎
- 100話を超える連載では、`.novel/config.json` の `limits.summary` を 6,000〜8,000 に上げると、全体の流れと直近の話の両方に余裕ができます
- 人物の力・持ち物・関係のいまの姿は、あらすじではなく人物の状態の記録が運びます（毎話 `novel_update(character-state)`）。
  用語と設定は用語集と世界観が運びます。**あらすじに何でも詰めない**
- 張ったままの伏線は `novel_status` の伏線の数で見ます。回収の章が未定のものが増えたら、次の山のどこで回収するかを決めます

### 連載の軽い進め方

連載（`serial: true`）では、シーン設計を省いて書きはじめられます。1話が短く、場面も1つか2つだからです。

1. 次の山までの章別プロットを、5〜10話ぶんまとめて作る（1話に、出来事・進むもの・出る人物・引きの型の4つ）
2. `/write-chapters next 5` で続けて書く（1話ずつ別のセッションで書かせるので、会話が膨らみません。一度に10話まで）
3. まとめて書いたあとは、1話は自分で読む（`/novel-review`）。ずれに早く気づけます
4. 山を越えたら全体の流れを更新し、次の山のプロットを作る

### 1話に1つ、進んだものを置く

どの話にも「この話で何が変わったか」が一つ要ります。変わるものは、状況・関係・情報・主人公の力のどれかです。
章別プロットに「この話で進むもの」を1行書いておき、書けない話は前後の話にまとめます。

</serial-rhythm>

## 五、1話の組み立て

<episode>

### 形

| 部分 | 分量の目安 | すること |
|---|---|---|
| 冒頭 | 3行〜200文字 | 前の話の引きを受ける。場面か動作から入る。前回のあらすじを書かない |
| 中身 | 1,500〜3,000文字 | 場面は1つか2つ。1話に出来事を1つ。会話と動きで進める |
| 山 | 300〜600文字 | この話のいちばんの見どころ。短い文で |
| 引き | 1〜5行 | 次の話を開かせる一手 |

場面が3つ以上になる話は、2話に分けることを考えます。1話に出来事を詰めると、どれも薄くなります。

### 章末の引きの型

| 型 | 例 | 向いた話 |
|---|---|---|
| 新しい事実 | 　鑑定の板に出た名前は、俺のものではなかった。 | 謎を進める話 |
| 来訪・乱入 | 「見つけた」<br>　扉の前に、追放したはずの元仲間が立っていた。 | 山の入り |
| 決断 | 　なら、こっちから行く。俺は地図を畳んだ。 | 反応の話の終わり |
| 危機 | 　足元の床が、音もなく抜けた。 | 行動の話の途中 |
| 逆転の予告 | 　彼らはまだ知らない。その荷物持ちが、何を運んでいたのかを。 | 見返す前の話 |
| 関係の一歩 | 「……明日も、来ていい？」 | 日常・ラブコメの話 |

気をつけること：

- **毎話「危機」で切らない**。同じ型が3話続くと、読者は引きを信じなくなります。型を回します
- **次の話の冒頭で、引きを必ず受ける**。夢だった、見間違いだった、で流さない
- **山場の直後の話は、静かな引きでよい**（関係の一歩、次の種）。ずっと張りつめると疲れます
- 「逆転の予告」は語り手が先を知っている言い方なので、一人称の現在進行の語りでは使いにくい。使うなら三人称か、回想の語りで

</episode>

## 六、文体 — 語り手の声とテンポ

<voice>

### 一人称の語り

Web 小説とライトノベルでは一人称が多く使われます。一人称では、地の文がそのまま主人公の声になります。

- **語り手の性格を、地の文の言い回しで出す**（ぼやく、茶化す、淡々と数える、すぐ結論を出す）。台詞だけでなく地の文も、その人物が言いそうな言葉で書く
- **ツッコミと独白は地の文に置く**。「（心の声）」の括弧に頼りすぎない。括弧は、口に出しかけて飲み込んだ一言などに絞る
- **語り手が知らないことは書かない**。相手の心の中、自分の見えない表情、その場にいない人物の動きは書けない。見せたいなら別視点の回にする（下の「別視点の回」）
- **一人称の語（俺／僕／私）を、台詞と地の文でそろえる**（資料の「🗣️ ことばづかい」）

### テンポ

- 段落は1〜3文を基本にし、見せ場の前に1行だけの段落を置く
- 会話が続くところは、3〜4往復ごとに動作か語りを1行挟む（誰が話しているかを保つため）
- 空行は、会話のまとまりの切れ目、場面の中の小さな間、オチの前に1行。2行以上は続けない
- 説明は、要るところで1〜2文ずつ。3文を超えるなら、誰かに質問させるか、失敗させて見せる
- 漢字を開く（「事」→「こと」、「出来る」→「できる」、「其の」→「その」）。画面で黒く詰まって見える行を減らす

### 書き比べ1：語り手の声

❌ **声の無い一人称**（三人称の「彼」を「俺」に替えただけ）
> 　俺は冒険者ギルドの扉を開けた。中には多くの冒険者がいた。受付には若い女性が座っていた。俺は緊張しながら受付に向かった。

✅ **声のある一人称**
> 　扉を開けた瞬間に後悔した。
> 　昼間から酒を飲んでいる大男が6人。全員こっちを見た。うち2人は斧を抱えている。なんで室内で斧を抱えているんだ。
> 　受付は奥だ。つまり、あの6人の横を通る必要がある。
> 　帰りたい。

**どこが違うか**：後者は、見えたものを主人公の言葉で数え、ツッコミを入れ、結論（帰りたい）を1行で落としています。「緊張した」とは書いていません。

### 書き比べ2：説明の入れ方

❌ **説明の段落**
> 　この世界にはスキルというものがある。スキルは15歳の成人の儀で神から授けられ、その種類によって人生が決まると言われている。スキルには等級があり、上から順に神級、王級、上級、中級、下級と分かれている。

✅ **場面の中で、要るぶんだけ**
> 「〈荷運び〉。下級」
> 　神官は板を読み上げて、次の者を呼んだ。それで終わりだった。
> 　後ろで誰かが笑った。隣の列では、王級を引いた商家の息子が胴上げされている。
> 　15年待って、もらえたのが荷物を持つ才能。

**どこが違うか**：等級があること、成人の儀で授かること、それで扱いが決まることが、出来事の中で伝わります。全部の等級の名前は、いまは要りません。

### 書き比べ3：AI くさい見せ場

❌
> 　その瞬間、俺の中で何かが弾けた。まるで世界が止まったかのようだった。体の奥底から、今まで感じたことのない力が溢れ出してくるのを感じた。

✅
> 　重い、と思わなかった。
> 　背負っていたはずの荷が、ない。いや、ある。肩紐は食い込んでいる。なのに足が軽い。
> 　試しに、落ちていた岩を背負子に放り込んだ。
> 　変わらない。
> 　もう1つ。変わらない。
> ……これ、もしかして、いくらでも入るのか？

**どこが違うか**：「力が溢れた」と言わず、主人公が試して確かめる手順を見せています。読者は主人公と同時に気づきます。

</voice>

## 七、特殊な回の書式

<formats>

ステータス画面や掲示板は、地の文と違う形で書きます。形は作品の中でそろえ、初めて出す話で決めた形を最後まで使います
（決めた形を `.novel/concept.md` の「文体と手ざわり」か `.novel/world-building.md` に1つ書いておくと、資料に載ります）。

共通の決まり：

- **前後の地の文とは空行で分ける**
- **見出し・項目・箇条書きの行は字下げしない**（`【】` などの開き括弧、`・` `■` などの記号、「項目：値」で始まる行は、表記の点検で字下げを求められません）
- **数は半角の算用数字**。日本語と英数字のあいだに半角スペースを入れない（`剣術Lv3`、`HP：38／38`）
- **スキル名・称号の括弧は `〈〉` か `【】`**。`《》` は漢字の直後に置くとルビとして読まれます（`必殺技《スラッシュ》` は「必殺技」に「スラッシュ」のルビ）。括弧として使うなら `｜《` と書きます
- **画面を出したら、主人公に反応させる**。数字を並べたまま次へ進まない

### ステータス画面

```text
　頭の中で唱えると、半透明の板が目の前に開いた。

【ステータス】
名前：ミナト
年齢：15
レベル：1
HP：38／38
MP：4／4
スキル：〈荷運び〉Lv1

……弱い。
　分かってはいたけれど、数字で見ると改めて弱い。MPの4は何に使うんだ。
```

- **全部を毎回出さない**。2回目からは、変わった行だけを出す（下）
- **出すのは節目だけ**（レベルが上がった、スキルを得た、強敵の前）。1話に1回まで
- 項目の並びと名前は、作品の中で変えない（人物の状態の `attributes` に同じ項目名で記録する）

```text
【ステータス】
レベル：1 → 4
スキル：〈荷運び〉Lv1 → Lv3
スキル：〈収納〉Lv1（新規）

「……は？」
　声が出た。スライムを3匹、背負子に入れて運んだだけだ。
```

### 通知・システムメッセージ

```text
＜スキル〈収納〉を取得しました＞
＜称号【運び屋】を獲得しました＞

　いや、待ってほしい。まだ何もしていない。
```

通知は1〜3行に抑えます。同じ通知が続くときは、地の文でまとめます（「同じ表示が、あと4回続いた」）。

### 掲示板回

作中の人々が、主人公のことを外から語る回です。読者は真相を知っていて、書き込む側は知らない、というずれを楽しませます。

```text
【朗報】新人が単独で第5層を抜けた件

1：名無しの探索者
　マジで？　ソースは

2：名無しの探索者
　ギルドの掲示に出てる。登録3日目らしい

3：名無しの探索者
　3日で第5層は無理だろ。荷物持ちでも雇ったんじゃないのか

4：名無しの探索者
　＞＞3
　本人が荷物持ちなんだよなあ
```

- 番号と名前の行は字下げせず、書き込みの本文は字下げします。書き込みのあいだは空行で分けます
- **書き込みの文末に句点を付けない**書き方でかまいません（掲示板の口調）。口調は書き込む人ごとに変えます
- 1回の掲示板は10〜20件まで。筋を進める書き込み（新しい目撃、誤解、次の噂）を3つは入れます
- 実在の掲示板やサービスの名前・書式をそのまま使いません。作中の名前にします
- 掲示板だけで1話を作るなら、幕間として書けます（`/write-chapter interlude 12`。章の数に入りません）

### 配信回

主人公の行動と、それを見ている人の反応を交互に置きます。

```text
　カメラの位置を直して、俺は第3層の扉に手をかけた。

＞待ってた
＞今日こそボス行く？
＞その装備で大丈夫か

「大丈夫じゃないです。でも行きます」

＞草
＞正直でよろしい
＞同接：1,204
```

- コメントは `＞` で始め、字下げしません。1度に2〜4行。行動の区切りごとに挟みます
- **コメントに筋を進めさせる**（警告する、気づく、煽る、情報を出す）。相づちだけのコメントを並べない
- 同時接続数などの数字は、節目でだけ動かします（数字が動くこと自体がごほうびになります）
- 配信者の台詞（「」）と、口に出さない語り（地の文）を分けます。視聴者に聞こえているのは台詞だけです

### 別視点の回

一人称の作品で、主人公に見えないもの（相手の評価、裏で動く者）を見せる回です。

```text
◆ギルド受付嬢・リタ

　変な新人が来た、というのが最初の感想だった。
```

- 回の頭に、区切りの行か、誰の視点かを示す1行を置きます（`◆` などの記号で始める。字下げしない）
- **回の中では視点を替えない**。主人公の回と同じ出来事をなぞるだけにしない（主人公が知らないことを1つは入れる）
- 短い別視点は、話の後半に区切りの行を置いて入れます。1話まるごとなら、章として書くか、幕間にします
- 別視点の語り手の一人称と口調は、人物設定の「ことばづかい」どおりにします
- 続けて2話以上、主人公から離れない（読者は主人公を読みに来ています）

</formats>

<checklist>

`/novel-review` で緩急（`--focus=pace`）を見るときに、Web 連載では次も見ます。

| 観点 | 見ること |
|---|---|
| 第1話 | 主人公の困りごと・作品の「売り」が動く場面・引きの3つがあるか。世界の説明から始まっていないか |
| 題との一致 | 題とログラインで約束したものが、第3話までに出ているか |
| 進んだもの | この話で変わったものを1行で言えるか（状況・関係・情報・力） |
| 分量 | 1話が目安（`novel_context` の「この章の目安」）に収まっているか。場面が3つ以上なら分けられないか |
| 引き | 章末に引きがあるか。前の2話と同じ型になっていないか。前の話の引きを冒頭で受けているか |

| 語り手の声 | 一人称の地の文が、主人公の言葉になっているか。「彼」を「俺」に替えただけの文になっていないか |
| 説明 | 3文を超える設定の説明が、場面の外に置かれていないか |
| 画面の書式 | ステータスや通知の形・項目名が、前の話と同じか。画面のあとに主人公の反応があるか |
| 特殊な回 | 掲示板・配信・別視点が、筋を進めているか（主人公が知らないこと、新しい情報が入っているか） |

## 九、投稿の準備

<publish>

題・キャッチコピー・紹介文・タグは、本文より先に読まれます。ここで読まれなければ、第1話は開かれません。
`/novel-publish` で作り、`.novel/publish.md` に残します。

> 文字数や個数の上限、ジャンルや区分の名前は、投稿先ごとに違い、変わることもあります。下の数字はカクヨムを例にした目安です。
> **入力する前に、投稿画面で確かめてください。** キャッチコピーの文字数とタグの数は `novel_status` が数え、カクヨムの上限（35文字・8個）を超えていれば知らせます。

### 題

| 作り方 | 形 | 向く作品 |
|---|---|---|
| 中身を言い当てる長い題 | 「[主人公の立場]が[売りになる出来事・力]で[向かう先]」 | Web 連載。一覧で題だけを見て選ばれるとき |
| 短い題＋副題 | 「短い題　〜中身を言う副題〜」 | 本にまとめるつもりがあるとき。短い題で覚えてもらい、副題で中身を伝える |
| 短い題だけ | 一語か二語 | 文芸寄り、公募。一覧では中身が伝わりにくい |

- 題で約束したものは、第1話に出す（「二、序盤3話の設計」）
- 題に入れるのは、主人公・売り・行き先のうち2つか3つ。型の名前（追放、転生、配信）は、読者が探す語なので入れてよい
- 同じ題の作品が無いか、投稿先で検索して確かめる。既にある有名な作品に寄せた題にしない

### キャッチコピー

一覧で題の上や横に出る、短い1行です（カクヨムは35文字まで）。

- 題の言い直しにしない。題が「何の話か」なら、キャッチコピーは「どこが面白いか」「どんな気持ちになるか」
- 主人公の台詞、作品の問い、意外な組み合わせのどれかで作る
- 句読点や記号も1文字。候補を出したら、文字数を1つずつ数えて添える

### 紹介文

| 位置 | 書くこと |
|---|---|
| 最初の1〜2行 | 売りを言い切る。一覧では冒頭だけが見えるので、ここで決まる |
| あらすじ | 主人公・状況・最初の出来事・向かう先。最初の山の入口まで。**結末や、中盤の驚きは書かない** |
| 読みどころ | 2〜4項目（型、関係、読後感。「ざまぁあり」「恋愛は遅め」など、読者が選ぶ手がかり） |
| 知らせ | 更新の予定、完結済みか、ほかのサイトにも載せているか |
| 注意書き | 二次創作なら原作名と作品の形（`novel-fanfic` skill の「注意書きに書くこと」）。残酷な描写などの注意 |

- 全体で200〜400文字。長くても600文字ほど
- 本文と同じ語りの調子で書く（軽い作品なら軽く）。「〜する物語である」の説明調にしない
- 本文に無いことを書かない。まだ書いていない先の展開を約束しすぎない

### タグ

- 読者が検索する語を選ぶ（カクヨムは8個まで）。次の4種から2個ずつが目安
  - **型**（異世界転生、追放、ダンジョン配信）
  - **要素**（主人公最強、成り上がり、ハーレム、スローライフ）
  - **関係・人物**（幼なじみ、師弟、年の差）
  - **読後感・調子**（ほのぼの、シリアス、コメディ）
- 作品に無い要素のタグを付けない（釣るためのタグは、読者を怒らせます）
- 二次創作は、投稿先の決まりに従って原作名などのタグを付ける

### ジャンル・区分・表示

- **ジャンル**は投稿先の選択肢から1つ選ぶ（いちばん近いものを。迷ったら、同じ型の作品が多いほう）
- **年齢や描写の区分**（カクヨムなら、残酷描写・暴力描写・性描写の有無）は、作品の中身に合わせて正直に付ける
- **生成 AI を使った作品の表示**やタグを求める投稿先があります。求められていれば従います
- 二次創作の可否は投稿先ごとに違います（`novel-fanfic` skill の「権利と、投稿先の決まり」）

### 本文を投稿欄に入れる

```
novel_export(split: true, unit: "話")
```

`.novel/export/episodes/` に、1話ずつのファイル（本文だけ）と `index.txt`（題と文字数の一覧）ができます。
投稿先の題の欄に `index.txt` の題を、本文の欄にファイルの中身を貼ります。ルビと傍点はカクヨムの記法のまま出るので、
ほかの投稿先なら `ruby`（`narou`、`pixiv` など）を渡します。

`.novel/config.json` に `"chapterUnit": "話"` を書いておくと、`unit` を省いても「第1話」になります。
カクヨムの「章」（話をまとめる見出し）に当たる部（`parts`）の見出しは、`index.txt` に「■ 第1部　…」として出ます。

### 公開の前に

- [ ] 書き出しの前に `novel_check` で表記の ❌ が無いことを確かめたか
- [ ] 第1話に、題とキャッチコピーで約束したものが出ているか
- [ ] 数話ぶんの書きためがあるか（更新が止まると読者は離れます。最初の山まで書いてから始めると安定します）
- [ ] 投稿先の規約（二次創作、年齢の区分、生成 AI の表示）を確かめたか

</publish>
